# 记忆模块输出(实测整理)

- **日期**:2026-07-01
- **来源**:`perception_qwen/memory_perception_report_sim.py` 在 4 相机 + 3 cube 场景实跑,真实感知(:5601 Qwen)喂入记忆,跑 5 回合(pick_and_place,全成功)。
- **原始数据**:`logs/mem_perc_report/report_sim.json`;磁盘记忆:`logs/mem_perc_report/store/{episodes.jsonl,episodes_meta.json,semantic_kb.json}`。
- **说明**:store 累计了我两次运行的数据(所以下方部分计数为 10 = 2×5),这本身也演示了跨运行持久化累积。

---

## 总览:三层记忆 + 规划成品

| 层 | 内容 | 本次数值 |
|---|---|---|
| 工作记忆 Working | 当前这一局的实时状态(清空重来) | 1 步动作,真实关节/夹爪 |
| 情景记忆 Episodic | 跨回合原始轨迹 + 遗忘 | 在库 5 条,历史共 10 条(老的已删) |
| 语义记忆 Semantic | 蒸馏出的长期知识 | pick_and_place 成功 10 次、cube@table×10 |
| PlanningContext | 交给规划器的成品 | 推荐技能序列 + 100% 成功率 + 相似回合 |

## 2. 情景记忆 Episodic Memory(跨回合原始轨迹 + 遗忘)

```json
{
  "total_episodes": 5,          // 在库原始回合(仅最近一次的 5 条)
  "episode_counter": 10,        // 历史累计存过 10 条
  "abstracted_episodes": 5,     // 已被归纳进语义层
  "success_rate": 1.0,
  "activation_stats": { "min": 0.0736, "max": 0.3432, "mean": 0.2421 }  // 激活在衰减
}
```
> **★ 遗忘已生效**:第一次运行的 5 条原始回合已被 `prune()` 删除(又老、激活 <0.05、且已归纳),
> 磁盘 `episodes.jsonl` 只剩 5 行。这是设计的"情景记忆遗忘原始轨迹"行为。

## 3. 语义记忆 Semantic Memory(蒸馏的长期知识 —— 记忆真正"学"到的)

`semantic_kb.json` 全文:
```json
{
  "object_kb": {
    "cube":   { "affordances": [], "location_freq": { "table": 10 }, "grasp_count": 0, "total_count": 10 },
    "target": { "affordances": [], "location_freq": { "table": 10 }, "grasp_count": 0, "total_count": 10 },
    "ee":     { "affordances": [], "location_freq": { "table": 10 }, "grasp_count": 0, "total_count": 10 }
  },
  "user_pref": {},
  "task_schema": {
    "pick_and_place": {
      "success_count": 10,
      "fail_count": 0,
      "common_steps": ["grasp cube"],
      "blueprint_skills": ["move_above", "descend", "grasp", "lift", "place", "retreat"]
    }
  },
  "spatial_topo": {
    "nodes": { "table": { "neighbours": [], "object_freq": { "cube": 10, "target": 10, "ee": 10 }, "pose": null } },
    "edges": []
  }
}
```
> **★ 知识留存**:原始回合被删了,但"pick_and_place 成功 10 次 / cube 常在 table / 推荐这套技能序列"
> **留在了语义记忆里**。这就是"遗忘原始轨迹、保留提炼知识"。
> 注:`affordances`/`grasp_count` 为空,是因为回合动作字符串是 `"grasp cube"`(含 cube 但不含 "pick"),
> 归纳逻辑判 grasped 需动作里同时含 "pick" + 物体名;这是可调的小口径问题。

## 5. 一句话解读

这次输出正好展示了记忆的**完整生命周期**:
**原始回合进情景记忆 → 每 5 回合蒸馏进语义记忆 → 老回合被遗忘删除 → 提炼知识留在语义层 →
汇总成 PlanningContext 交给规划器**。三层 + 归纳 + 遗忘 + 持久化,全在真实仿真数据上跑通。

- 持久化:`persistence_ok = true`(重开进程读同一 store,成功率一致)。
- 局限:`recent_actions` 只有 1 步、`common_steps` 单一,是因为每回合只记了 1 个动作(测试脚本简化);
  接真规划器后动作序列会更丰富。
