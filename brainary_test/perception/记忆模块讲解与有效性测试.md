# 记忆模块(xiaoyu / Brainary Memory)功能讲解 + 有效性测试方案

> 面向:把感知模块(本目录 lianyu)接进记忆模块后,想搞清楚"记忆到底在干什么、怎么证明它有用"。
> 依据:通读 `xiaoyu/brainary_memory_pkg/embodiedbench/memory_manip/*` 与 `memory_module/*` 源码。
> 日期:2026-07-01。

---

## 一、一句话定位

记忆模块是一个**「感知 → 记忆 → 规划」的中间层**:它不做识别、也不做控制,而是把每一步的
感知结果、动作结果、机器人状态**存起来、跨回合归纳成知识**,再在需要时把"历史经验"打包成一个
`PlanningContext` 喂给规划器/VLM。核心价值是:**不重新训练模型,靠外部记忆让系统跨回合越用越聪明**。

---

## 二、三层记忆分别是什么(基于源码的准确描述)

### 1. 工作记忆 Working Memory(单回合、易失,`begin_episode` 时清空)
当前这一局的"短期草稿纸":
- `goal`:任务指令 + 意图(5-Whys intent)
- `observation`:当前可见物体 `visible_objects`、场景文本、物体属性、当前语义位置、手里拿的物体
- `action_buffer`:最近动作 + 成败 + 反馈(上限 32 条,配置 `action_buffer_max`)
- `robot_state`:末端位姿 / 关节 / 夹爪开度 / 力矩
- `clock`:回合步数 + 里程碑

### 2. 情景记忆 Episodic Memory(跨回合、持久化 `episodes.jsonl`)
每个回合存一条完整轨迹 `EpisodeRecord`(所有步、遇到的物体、blueprint 技能序列、成败)。两大机制:
- **相似检索**(`StringRetriever`):按**关键词重叠**给历史回合打分 = 指令重叠 ×0.7 + 物体重叠 ×0.3,
  取 top-k(默认阈值 0.1)。⚠️ 注意:是**词面重叠,不是语义 embedding**。
- **ACT-R 激活/遗忘**:`activation = initial_score·exp(-decay·age) + log1p(access_count)·boost`
  (默认 decay=0.5、boost=0.3)。回合越老激活越低;每次被检索到会 +一点(reactivate);
  被泛化过(abstracted)且激活 < 0.05 的回合会被 `prune()` 删除。

### 3. 语义记忆 Semantic Memory(长期知识、持久化 `semantic_kb.json`)
从情景记忆**归纳**出的世界知识,四个库:
- `ObjectKB`:物体 → 可供性(pick…)+ 历史出现位置频率
- `TaskSchema`:任务类型(关键词推断:pick_and_place / open_container / …)→ 成功/失败次数、
  常见动作序列、**推荐 blueprint 技能序列(只有成功的回合才会更新这个推荐)**
- `UserPreference`:功能需求 → 偏好/规避物体(显式 > 情景推断)
- `SpatialTopo`:位置拓扑图 + 各位置物体频率
- **归纳时机**:每完成 **5 个回合**(`episodic_generalize_every_n=5`)批量把情景 → 语义。

### 4. 门面 + 规划接口
`EmbodiedManipulationMemorySystem` 统管三层;`PlanningMemoryInterface.get_planning_context()`
把三层聚合成一个 `PlanningContext`(可见物体、推荐技能、成功率、相似历史、物体位置先验、
用户偏好、最近动作…),`export_context_for_vlm()` 落成 `memory_context.json` 给 VLM Brain。

## 三、数据流

```
感知(lianyu)→ process_perception(image_paths, scene_state)
   ├─ VisionPerceptionAdapter:RecognitionResult → (T,P,D)特征 + visible_objects/属性 → working
   └─ ingest_scene_state:cube/target/ee 位姿 + 关节 → working.robot_state
每步:get_planning_context() → PlanningContext(给规划器/VLM)
每步:record_action(动作,成败) → working.action_buffer
回合末:end_episode(success, blueprint_skills) → 存 episodic;每5回合 → 归纳进 semantic
```

## 四、"有效性"到底指什么(先把命题说清楚,才能测)

## 五、可证伪的测试清单

> 原则:**先隔离测记忆逻辑本身(A–E,不需要 VLM/仿真,秒级、确定性),再测闭环增益(F)**。
> A–E 用**受控/GT 输入**,把记忆机制和"Qwen 识别噪声"解耦——否则分不清是记忆的问题还是感知的问题。

### 测试 A — 任务学习:成功率与推荐技能积累 ★核心
- **做法**:同一任务类型跑 6 个回合,人为设定成败(如 4 成功 2 失败),每个成功回合传入
  `blueprint_skills=["move_above","descend","grasp","lift","place","retreat"]`,失败回合传个不同/空序列。
- **通过判据**(全部满足才算有效):
  1. 第 5 回合结束后触发归纳,`get_task_schema()["success_rate"]` ≈ 真实比例(4/6≈0.67)。
  2. `recommended_skills` 从**空 → 等于最后一次成功回合的序列**。
  3. **失败回合不会覆盖推荐序列**(源码:`record_blueprint_skills` 只在 success 时写)。
- **证伪**:若跑完 6 回合 `recommended_skills` 仍为空,或被失败序列污染 → 无效。

### 测试 B — 相似回合检索
- **做法**:存入若干不同指令的回合(如 3 个 "pick up the cube"、2 个 "open the drawer"),
  用新指令 `"pick up the red cube"` 查询。
- **通过判据**:返回的 top-k 都是 cube 相关回合(指令/物体关键词重叠高),drawer 回合被排除或排在后面。
- **证伪**:若 drawer 回合排在 cube 前面 → 检索无效。⚠️ 已知局限:词面匹配,"grab the block" 查
  "pick up the cube" 不会命中(无语义)——测试要用词面可重叠的指令,或据此判定"需要升级为 embedding 检索"。

### 测试 C — 物体位置先验
- **做法**:多个回合里让 `cube` 反复在 `table` 出现(step 的 current_location="table")3 次、`shelf` 1 次,
  且有 "pick cube" 动作(触发 grasped)。跑满 5 回合触发归纳。
- **通过判据**:`get_object_info("cube")["likely_locations"]` = `[("table",N_table),("shelf",N_shelf)]`
  且 table 频次 > shelf;`PlanningContext.object_location_priors["cube"]` 首位是 `table`;affordances 含 `pick`。
- **证伪**:先验顺序与真实频率不符 → 无效。

### 测试 D — 激活衰减与遗忘(记忆的"忘"也是功能)
- **做法**:存 1 条回合,记初始激活 = `initial_score`;不断推进 episode 计数(多存几条无关回合)让其 age 增大,
  周期性 `decay_and_prune()`;再单独测:检索命中一次后激活是否回升。
- **通过判据**:
  1. age=0 时激活 = initial_score;age=k 时 ≈ `initial_score·e^(-0.5k)`(数值对得上公式)。
  2. 被检索到后 `access_count`+1、激活按 `+log1p·0.3` 回升(近因/常用不易忘)。
  3. abstracted 且激活 < 0.05 的回合被 `prune()` 删除,`episodes.jsonl` 里真的没了。
- **证伪**:激活不衰减 / 剪枝不生效 / 检索不回升 → 遗忘机制无效。

### 测试 E — 持久化与崩溃安全
- **做法**:写入若干回合 + 触发归纳 → **销毁内存对象** → 用**同一个 `store_dir`** 重建
  `EmbodiedManipulationMemorySystem` → 再查。
- **通过判据**:`success_rate` / `recommended_skills` / 物体先验 / 情景条数 与重启前**完全一致**;
  且写入用的是 `.tmp`→`os.replace` 原子写(断电不损坏)。
- **证伪**:重启后知识丢失或读不回 → 持久化无效。

### 测试 F — 闭环增益 A/B(真正的"有用"证明)★金标准
- **做法**:**同一批任务跑两遍**:
  - 基线臂:每回合用**空记忆**(不注入 PlanningContext)。
  - 记忆臂:跨回合积累,把 `recommended_skills` / `object_location_priors` / `similar_episodes`
    注入规划器/VLM 提示。
- **度量**(记忆应改善的下游指标,至少一项显著更好):任务成功率↑ / 规划步数或重试次数↓ /
  首次尝试就用对技能序列的比例↑。
- **通过判据**:在**足够多回合**上,记忆臂在选定指标上**统计显著**优于基线臂。
- **证伪**:两臂无差异 → 记忆对下游"没用"(哪怕 A–E 全过,也只是"存对了"但"没帮到")。

## 六、建议的执行顺序

1. **先跑 A–E(离线、纯记忆逻辑,不启 Qwen/仿真)** —— 几秒钟、确定性、可写成 `pytest` 断言。
   这一步证明"记忆机制本身正确"。**这是证明有效性性价比最高的一步**。
2. **再跑 F(接感知+仿真的闭环 A/B)** —— 证明"记忆确实改善了任务表现"。成本高、需要多回合统计,
   但这才是给别人看的"有用"证据。可复用已搭好的 `memory_integration_test.py` 扩成多回合 A/B。

## 七、诚实的已知局限(测的时候要避开或据此下结论)

- **检索是关键词重叠,非语义 embedding** → 换个说法的同义任务检索不到(测试 B 会暴露,可作为"改进项")。
- **task_type 靠关键词推断** → 指令措辞刁钻会归错类。
- **记忆不校验感知对错** → 感知喂错(如 Qwen 把冰箱认成打印机)会原样存进记忆(garbage in/out)。
  所以 A–E 必须用 GT/受控输入隔离,别让 Qwen 噪声混进来。
- **scene_state 只要有 `xxx_pose` 键就把 xxx 当可见物体**,不校验坐标合理性
  (集成测试里 cube 停在场外 [100,100,-22860] 仍被当"可见")→ 闭环测试要只喂在场的有效物体。
- **默认 `embodiedltm_base_url="http://127.0.0.1:8000"`** 远程 LTM 服务:没起就会连不上;
  我们的用法一律传 `embodiedltm_base_url=None` 关掉,避免干扰。
