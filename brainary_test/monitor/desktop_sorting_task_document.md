## 一、任务概述
本任务旨在通过机械臂对桌面上的散落物品进行分类整理，将其收纳到指定篮子中。任务涉及 **Planner 模块（规划）**、**Simulation 模块（仿真验证）**与 **Project Management 模块（多线程优化）**三个模块的协作处理。

桌面物品包括食品类（香蕉、橘子）、杯具类（蓝色杯子、黄色杯子）以及工具类（剪刀、大食品盒），需分别放入三个对应篮子中。由于桌面物品呈密集排布状态，机械臂在抓取目标物品时可能受到周围物品的遮挡，需要三个模块协作处理遮挡感知、仿真验证与执行优化。

## 二、场景与物品

### 2.1 可用设施
| 设施名称 | 位置 | 用途 |
|---|---|---|
| 篮子一 | 桌面右侧前排 | 收纳食品类物品 |
| 篮子二 | 桌面右侧中排 | 收纳杯具类物品 |
| 篮子三 | 桌面右侧后排 | 收纳工具类物品 |

### 2.2 桌面物品
| 物品名称 | 类别 | 目标篮子 |
|---|---|---|
| 香蕉 | 食品类 | 篮子一 |
| 橘子 | 食品类 | 篮子一 |
| 水杯一（蓝色） | 杯具类 | 篮子二 |
| 水杯二（黄色） | 杯具类 | 篮子二 |
| 剪刀 | 工具类 | 篮子三 |
| 大食品盒 | 工具类 | 篮子三 |

### 2.3 物品位置关系
大食品盒位于香蕉和橘子的外侧，由于高度较高且与水果紧密相邻，机械臂夹爪从上方接近水果时可能会碰撞到大食品盒。此外，杯子也可能与水果相邻放置，形成额外的遮挡关系。水杯一和水杯二位于桌面左侧，剪刀位于桌面中央，均为独立放置。

## 三、任务分层架构
本任务采用三层架构设计，从简略指令到子任务拆解，再到三模块协作流程，逐层细化任务的执行粒度。

### 3.1 第一层：简略指令
> "把食品放到篮子一，把杯子放到篮子二，把文具放到篮子三。"

该层以最简洁的自然语言表达任务目标，不涉及具体执行细节、遮挡关系或物品属性，仅明确分类目标与对应收纳位置。

### 3.2 第二层：子任务拆解
将简略指令拆解为可独立执行的子任务，每个子任务对应一个明确的分类目标：

| 子任务编号 | 子任务名称 | 目标 | 说明 |
|---|---|---|---|
| 子任务一 | 食品入篮子一 | 香蕉、橘子 | 将食品类物品放入篮子一 |
| 子任务二 | 杯具入篮子二 | 水杯一、水杯二 | 将杯具类物品放入篮子二 |
| 子任务三 | 工具入篮子三 | 剪刀、大食品盒 | 将工具类物品放入篮子三 |
| 子任务四 | 持续监测收尾 | 桌面所有区域 | 扫描桌面直至完全清空 |

### 3.3 第三层：三模块协作流程
该层详细描述 Planner 模块、Simulation 模块与 Project Management 模块的协作处理流程。

#### 3.3.1 Planner 模块 —— 中粒度任务序列
Planner 模块接收第一层简略指令，按语义类别规划中粒度任务序列。该模块不感知物品间的空间遮挡关系，仅根据物品类别进行规划。

**Planner 模块输出的初始中粒度任务序列如下：**

| 步骤 | 操作 | 条件 |
|---|---|---|
| T1 | 抓取大食品盒 | 无 |
| T2 | 将大食品盒放入篮子三 | T1 完成 |
| T3 | 抓取香蕉 | 无 |
| T4 | 将香蕉放入篮子一 | T3 完成 |
| T5 | 抓取橘子 | 无 |
| T6 | 将橘子放入篮子一 | T5 完成 |
| T7 | 抓取水杯一 | 无 |
| T8 | 将水杯一放入篮子二 | T7 完成 |
| T9 | 抓取水杯二 | 无 |
| T10 | 将水杯二放入篮子二 | T9 完成 |
| T11 | 抓取剪刀 | 无 |
| T12 | 将剪刀放入篮子三 | T11 完成 |

Planner 模块具备持续监测能力，若桌面出现新物品，可增量规划新任务。例如：若新出现杯子类物品，自动新增 "抓取杯子 -> 放入篮子二" 的任务条目。

#### 3.3.2 Simulation 模块 —— 发现遮挡，调整执行顺序
Simulation 模块对 Planner 输出的序列逐条进行物理仿真验证，发现遮挡问题并调整执行顺序：

| 仿真步骤 | 操作 | 结果 |
|---|---|---|
| S1 | 仿真 T1（大食品盒入篮） | 通过 |
| S2 | 仿真 T3（抓取香蕉） | **失败！**被大食品盒遮挡 |
| S3 | 仿真 T5（抓取橘子） | **失败！**被大食品盒遮挡 |
| S4 | 仿真 T7（抓取水杯一） | 可能失败！被水果遮挡 |
| — | **调整顺序：先移开遮挡物** | **解决遮挡问题** |

Simulation 模块调整后的执行序列中，大食品盒和杯子被临时移开以让出路径，水果放入后再将遮挡物放回目标篮子。此方案解决了遮挡问题，但引入了冗余步骤。

#### 3.3.3 Project Management 模块 —— 消除冗余，一步到位
Project Management 模块分析 Simulation 的输出，识别冗余并优化执行方案：

| 模块 | 原始方案 | 优化方案 | 效果 |
|---|---|---|---|
| Simulation | 遮挡物先临时移开，再放回目标篮 | — | 引入冗余步骤 |
| PM | — | **遮挡物一步到位直接入目标篮** | **消除冗余，减少操作次数** |

Project Management 模块的核心价值在于将 Simulation 方案中的 "临时移开再放回目标篮" 优化为 "一步到位直接入目标篮"，消减了冗余的中间步骤，减少了机械臂的抓取和放置动作次数。

## 四、先决条件与约束
- 桌面初始状态混乱，物品之间的遮挡关系未知，机械臂必须通过实时碰撞检测动态判断。
- 三个篮子严格按类别限制使用：篮子一仅放食品类，篮子二仅放杯具类，篮子三仅放工具类，不可跨类别混放。
- 当抓取目标时若检测到路径遮挡，系统必须查询遮挡物的类别：
  - 若该遮挡物也在收纳清单中，则切换子任务直接收纳该遮挡物到对应篮子；
  - 若不在清单中，则需移开后再抓取。
- **Planner 模块**负责生成中粒度任务序列和条件分支，原始方案可能包含冗余的中间步骤。
- **Simulation 模块**负责验证物理可行性和堆叠约束，发现并解决遮挡问题。
- **Project Management 模块**负责跨子任务的重新排序和粒度优化，消除冗余动作，实现一步到位。

## 五、三模块协作总结
| 模块 | 职责 | 处理的问题 |
|---|---|---|
| **Planner** | 按类别规划中粒度任务序列 | 条件判断、增量规划 |
| **Simulation** | 仿真验证物理可行性 | 堆叠约束、遮挡检测、顺序调整 |
| **Project Management** | 消除冗余，一步到位 | 多线程优化、减少无用动作和空闲时间 |

三模块的协作流程为：`Planner 生成中粒度规划（可能含冗余） -> Simulation 验证可行性并调整顺序 -> PM 识别冗余并优化执行`。三个模块形成闭环，共同完成任务从规划到执行的完整链路。

## 六、持续循环机制
系统持续扫描桌面状态，检测到遗留物品或新出现物品时，触发 Planner 模块重新规划中粒度任务，经 Simulation 仿真验证后，由 Project Management 模块优化调度执行。循环持续进行，直至桌面完全清空。

> **流程循环**：Planner 规划 -> Simulation 验证 -> PM 优化 -> 机械臂执行 -> 检测遗留 -> Planner 重新规划
